# 02 · 8 GB 显存下的性能取舍

这份笔记基于 RX 5700 XT（8176 MB VRAM / 16194 MB RAM）实测日志，不是理论推算。

## 时间花在哪

一次完整出图（768×1152 底图 30 步 + 1.3× 放大 15 步）的日志：

```
100%|██████████| 25/25 [10:47<00:00, 25.66s/it]
100%|██████████| 25/25 [13:13<00:00, 31.74s/it]
Prompt executed in 00:12:41
```

拆开看：

| 阶段 | 占比 | 说明 |
|---|---|---|
| 采样（KSampler） | **≈ 95%** | 26 – 32 秒/步 |
| VAE 分块解码 | 3 – 5% | 十几秒 |
| 模型加载 / 换出 | 冷启动显著，热启动可忽略 | UNet 3988 MB |

**每步耗时随分辨率线性甚至超线性增长**，因为 RDNA1 没有 flash/memory-efficient attention，注意力计算退化为更吃带宽的实现。

结论：任何优化，第一优先级永远是"少算几步"，而不是折腾后端。

## 显存花在哪

日志里的加载量：

```
loaded completely;  3988.40 MB loaded   ← Anima UNet (fp16)
loaded completely;  1136.88 MB loaded   ← Qwen3-0.6B 文本编码器
loaded completely;   242.03 MB loaded   ← VAE
```

UNet 一项就占掉 4 GB。加上 998×1497 的潜变量、激活值和注意力中间张量，8 GB 很紧。所以：

- **主模型一加载就几乎到顶**，第二个 LoRA 挂上来就会开始抖。
- 这就是为什么必须 `--enable-dynamic-vram`，也是为什么 VAE 解码要分块 —— 像素空间 1497 高的解码峰值能到 GB 级。

## 优化手段，按性价比排序

| # | 手段 | 效果 | 画质代价 |
|---|---|---|---|
| 1 | 第二段采样步数 15 → 10 | ≈ −25% 总时长 | 细节略软，肉眼几乎看不出 |
| 2 | 底图步数 30 → 20 | ≈ −30% 总时长 | 构图/大形轻微变化 |
| 3 | 放大倍率 1.3 → 1.15 | ≈ −25% 第二段耗时 | 分辨率从 998×1497 降到 883×1325 |
| 4 | LoRA 9 → 5（关掉叠加的次要风格） | 加载 −200 ms/个，显存 −几十 MB/个，**采样速度基本不变** | 风格差异明显 |
| 5 | 底图分辨率 768×1152 → 640×960 | ≈ −30%，且显著降低 OOM 概率 | 细节减少 |
| 6 | 关掉 `PreviewImage` 分支 | 省一次完整 VAE 解码（十几秒） | 失去低分辨率预览 |

第 4 条值得强调：**删 LoRA 几乎不提速**。LoRA 是权重合并，合完之后对每步计算量没有影响。它省的是加载时间和显存，不是采样时间。很多"9 个 LoRA 太慢"的直觉是错的 —— 慢的是步数和分辨率。

## 冷启动与 MIOpen 缓存

第一次跑某个分辨率 / 某个 shape 时，MIOpen 会现场编译 kernel，额外 5 – 10 分钟。编译结果缓存在：

```
C:\Users\<用户名>\.miopen
```

本机该目录只有 302 KB，说明大部分 kernel 走的是预编译路径，缓存命中率不高。可以做的：

- **固定分辨率**。每换一个宽高比就重新编译一批 kernel，反复换尺寸是最大的时间浪费。
- 备份 `.miopen` 目录，重装环境后还原，能省掉一批冷启动开销。

## 不建议做的事

| 别做 | 为什么 |
|---|---|
| `--highvram` | 8 GB 卡上会让 ComfyUI 不做换出，直接 OOM |
| `--use-split-cross-attention` | 日志已确认走 sub-quadratic 优化，换掉更慢 |
| 一次性加载多个大模型做快速切换 | 16 GB 内存会被撑爆，表现为整个进程卡死而不是报错 |
| 用 fp32 精度换"更准" | 显存直接翻倍，且 RDNA1 的 fp32 算力没有余量 |
| 把 tile 尺寸调到 1024 | 分块解码的意义就没了，峰值显存回到 3 GB |

## 如果你的机器更快

上面的数字是 8 GB / 16 GB RAM / 单卡的保守配置。12 GB 以上显存可以：

- 去掉 `VAEDecodeTiled`，直接用 `VAEDecode`
- 放大倍率提到 1.5
- 底图直接 896×1344 起步

工作流结构不用改，只改参数。
